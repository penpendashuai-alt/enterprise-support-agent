# 简历改进专项：冻结评测协议 v1

日期：2026-10-22。新 dev 输出观察前制定；pilot 独立记录，不并入结果。当前状态见 manifest.json 与 progress.md。

## 问题、候选及停止规则

优先检查审批草稿对请求、计划、否定、失败、他人经历和多轮纠正的忠实度，以及候选证据到最终上下文之间的损失。先观察冻结基线 dev；每个问题最多两轮候选。不得按 heldout 调参。若新 heldout 指导继续修改，必须转为回归集并另建留出集。

基线源码来自启动时 Git HEAD 的归档，归档摘要记录在 manifest.json。历史原始材料只读，1,052 个归档文件的摘要位于 baseline/historical-artifacts.sha256.json。候选运行前另存源码归档/逐文件摘要、参数与变更假设。

## 数据、独立性和分母

- 检索：120 条新合成查询，60 dev / 60 heldout，每部分 45 可答、15 无答案。文档主题家族隔离；每个可答主题包含两个条款问题及组合问题。
- Agent：80 个新合成任务，40 dev / 40 heldout，每部分 12 知识/边界、12 草稿、8 工具/查询、8 多轮/审批。任务家族跨划分不得重叠；多轮家族含两个试验，按家族聚合，不充当两项独立泛化证据。
- 语料仍为原有 36 篇资料、72 块，不能称为独立企业数据。新题的字符串去重不等于语义独立。知识任务从同部分检索题衍生，不能把两者样本数相加。
- 金标准包含定位条款、必需事实、禁止推断、可接受澄清与业务断言；无依据具体数字不得靠一般常识补齐。相同文档内能支持答案的等价片段可补充为 alternatives，但需在观察结果前校验。
- 同一开发助手参与设计、实现、审阅，非独立标注。语义审阅逐条保存判断依据；不能把简单字符串命中当作语义正确。评审展示随机化方案名，映射单独保存；不新增付费模型评审。

## 环境和成本

模型 deepseek-v4-pro，temperature=0，thinking=disabled，每请求最多 1,800 输出 tokens，SDK 重试为 0，单 worker。HTTP 层逐次预留并记账，应用重试同样被覆盖；未知用量/中断、金额或请求次数到限即停止。SQLite 事务防止多进程重复预留，当前合同只允许串行付费请求。供应商响应缓冲后才交 SDK，因此本实验不测模型 TTFT。

总预算 60 元（本会话已授权）；pilot 3、baseline 10、development 12、heldout 10、performance 22、最终 demo 3 元。聊天最多 1,200 次，Embedding 最多 700 次，重排与模型评审 0 次。按高峰无缓存单价上界记账，不扣免费额度或供应商缓存优惠，不冒充实际账单。价格已核对：[DeepSeek](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[DashScope](https://help.aliyun.com/zh/model-studio/embedding)。合同与价格摘要在 calls/contract.json。

正式云端 Qdrant 在 2026-10-22 预检时直连连接重置、代理 TLS EOF。因此使用独立本地 Qdrant 从冻结 snapshot_v2 重建正式 72 块索引，真实 text-embedding-v3 / 1024 维，导入消耗计入 pilot。此环境与历史云端不同，不能直接比较延迟。新 PostgreSQL 和 Redis 容器及每次新数据库/命名空间隔离业务数据。服务和设备查询仍为明确标注的模拟数据；DEMO 工单为真实数据库记录。

## 指标与审阅

1. 检索分别报告候选块 EvidenceRecall@5、候选全部条款覆盖、最终必要证据完整覆盖及平均条款覆盖。可答分母每部分 45；无答案分母每部分 15，单列返回任意证据，不把它等同于最终回答编造。
2. Agent 完整成功需结构、业务、语义均通过。全部预定 40 项均保留，未运行/依赖错误/模型错误分开；依赖错误不能从端到端分母消失。另报正常依赖子集及故障注入子集。
3. 草稿同时报告忠实草稿数/实际生成草稿数，及忠实完成数/预定可生成任务数；澄清、缺失与失败另列，不能靠全部澄清获得满分。所有明确事实均需保留正确主体、时间、动作状态。
4. 未批准写入、重复创建、过期版本批准成功、跨归属读写分别统计，任一违规使候选不通过。审批版本、指纹、唯一键和 unknown 核查语义不得削弱。
5. 配对结果记录均成功、仅基线成功、仅候选成功、均失败。报告比例分子/分母和 Wilson 95% 区间（描述性）；方案差值以 family 为簇进行 10,000 次 bootstrap，随机种子 20261022，保留簇内关联；任务重复不扩充独立样本。样本小不宣称普遍或显著提升。
6. 若评分契约有错误，保留原记录，修订协议并对两方案对称重算。不得为了分数仅修改一组金标准。

## 顺序、性能和最终验收

dev 基线先运行，按失败提出变更并保存反例。冻结候选后，heldout 对每个任务以 case_id 序号奇偶交替 AB / BA，相邻执行；固定同一模型、索引、预算、资源和评分。每个任务每方案一次，多轮重复按预定义家族处理。

真实检索缓存选择 dev 的至少 20 个不同查询，off / cold / warm，按查询轮换条件先后，每条件两次；cold 每次使用新命名空间，warm 先预热，记录预热调用但不算测量。输出证据一致性、外部调用和阶段计时。

真实 Agent 性能先每条件 20 次 pilot，之后根据预算/波动预先冻结确认规模，初始计划每条件 100 次。固定单并发，区分候选代码质量比较和缓存开关比较；报告全部尝试、成功率、总耗时、队列和阶段时间。P50 为中位数，P95 用 nearest-rank，家族/查询簇 bootstrap 区间；没有精度就不写 P95 改善。拒绝不计成功吞吐，不平均不同批次 P95。

本地确定性负载分别测 cold/hot/unique/mixed/same_thread，容量与过载分开，固定并发梯度、初始令牌桶与平衡顺序。记录所有 HTTP 拒绝与资源归零，不能作为真实模型吞吐。最终浏览器验收使用最终版本、真实聊天和正式 72 块索引，包含引用、无答案、缺失信息、编辑/旧批准、批准防重及恢复，并核对数据库。
