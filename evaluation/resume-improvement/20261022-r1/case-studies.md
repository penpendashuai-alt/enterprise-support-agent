# 从失败记录到候选改进

本次改动基于 `bfb68a0`，仅修改两个产品文件。开发集选择两轮候选后冻结；未按留出失败继续调参。开发、数据设计和语义审阅均由同一助手完成，属于非独立评测。

## 案例一：草稿的影响范围与事实状态

### 失败与原因

[开发样本 a-dev-14](baseline/agent-dev/a-dev-14.json) 明确说“我个人收不到外部邮件”“检查目前还没开始”，基线却继续询问影响范围，没有生成草稿。字段保守抽取把明确的受影响对象与未知影响范围混淆了。另一方面，[a-dev-33](baseline/agent-dev/a-dev-33.json) 同时把范围写入 description 和 impact，编辑 impact 为“三人小组”后，description 仍写“只影响用户本人”，结构校验虽通过，业务内容却矛盾。

源码入口为 `src/agents/ticket_flow.py:prepare_draft`。描述和影响范围均由模型提取，原指令未足够明确地划分字段责任。审批版本、数据库唯一约束能保护批准和写入的一致性，却不能自动判断草稿中的自然语言是否忠实。

### 改动与取舍

1. description 保存现象、时间和操作状态；影响对象归 impact，减少编辑后的重复事实残留。
2. impact 沿用用户明确的对象短语。“我个人”可作为明确报告对象，但不能擅自加强成“仅本人”；“我的电脑”只是所有权，不推断影响范围；明确未核实仍填 null。
3. 保留原有否定、未执行、失败尝试、后续更正和已结束工单边界规则。

v1 仍有范围扩写和设备路由问题，未采用。v2 没有增加模型调用或新的评审模型，保留用户批准、版本、指纹与数据库约束。代价是提示词变长，且仍不是确定性事实校验：例如 [v2 a-dev-14](development/agent-dev-v2-recovered/a-dev-14.json) 的 description 仍重复“我个人”。不能声称字段分工在所有输出上完全执行。

### 重测结果

开发集完整成功30/40→37/40，仅用于选择。新留出10个预期能生成草稿的任务中，生成且忠实完成4/10→9/10；已生成草稿忠实度是4/4和9/9。改善的是完成率，不是准确率从40%到90%。这10题来自5个家族的改写，且候选仍有1题未能生成草稿。

完整留出主结果为27/40→32/40，配对均成功25、仅候选7、仅基线2、均失败6；家族簇bootstrap差值区间约[-2.6,27.5]个百分点，包含0。知识问答有1项新增错误，另1项候选在数据库中断后未完成，均保留在主结果中。[原始与修订评分](protocol-amendments.md) 对两方案同时复算，不能只用总分宣称整体显著提升。

## 案例二：设备查询被知识库错误前置

[a-dev-27](baseline/agent-dev/a-dev-27.json) 请求 DEV-001 的系统与客户端配置。基线路由为 general_question，走文档检索后拒答，没有执行设备工具。v1 修正提示后仍暴露代码问题：`knowledge_required or intent == troubleshooting` 会把所有 troubleshooting 都强制检索，覆盖模型“无需知识检索”的决定。

候选在 Router 指令中保留用户设备编号，并将直接设备信息查询归入 troubleshooting。代码仅当有 device_id、没有 issue_description、且模型判定无需知识时允许直接走只读设备工具；实际故障、明确文档排障仍需检索。不能用一般的“有设备编号”条件把全部故障请求放行。

[v2 a-dev-27](development/agent-dev-v2-recovered/a-dev-27.json) 返回 DEV-001 的模拟 Windows 11 / VPN 5.0 配置，并说明是固定模拟数据。新增软件回归同时检查无知识索引设备查询、真实故障和显式文档查询三条边界。新留出工具类完整成功7/8→8/8；样本少，不宣称真实企业设备接口可靠性。

## 检索归因与未采用的方案

本轮 dev 检索45道可答题的候选 Evidence Recall@5为1，但最终完整覆盖43/45。vpn-policy-1、email-policy-3的必要证据因0.65分数门槛未进入最终证据，未观察到字符预算挤出。候选召回高不代表最终证据完整，更不代表生成回答正确。

本轮没有改动检索组件或重新调阈值。新留出完整覆盖38/45、无答案返回任何证据1/15，是当前Dense基线的绝对结果；与dev差异不是优化收益。历史7组对照中Hybrid提高覆盖同时增加无答案误接收，重排又损失必要证据，因此没有为增加组件而默认开启复杂组合。完整依据见 [派生数据](derived/supporting-evidence.json) 和仓库 `docs/rag_experiments.md`。
