# Phase 8 评分规则 v1

冻结日期：2026-10-03。评分对象为完整任务，计划 36 开发 / 24 留出；按 family_id 分组，相同多轮任务不拆成多个独立样本。历史失败和联通试运行另列，不计入正式 60 任务。

## 执行与结构

每轮 HTTP 状态、实际意图、实体、工具名称/参数/执行结果、引用编号校验、审批状态和 PostgreSQL 数量分别保存。一个合理路径可以包含多个允许工具，服务别名与大小写按工具实际语义归一；必需调用要求匹配实际参数并取得结果。工具返回 not_found 仍可能是正确执行，不能把它当作查询成功找到了资源；错误结果是否解释正确另做语义审阅。

票据任务检查草稿未批准时为 0、取消后为 0、修改后版本增加且重新批准、重复批准仍只有 1 张。审核最终响应和数据库。403 等预期身份拒绝可以是场景成功。任何 SSE error 或缺少 DONE 均记录失败，即使 HTTP 200。

## 语义审阅

开发助手参与场景设计、实现和审阅，属于非独立审阅，不称独立人工盲评。第一版不使用在线 Judge。每个判断绑定原始记录 SHA-256，记录审阅者、时间、规则版本、依据和不确定项。

- 必要要点使用数据集中的语义描述，检查是否被**本次实际提供的证据**支持并覆盖；不使用关键词包含来判断有据性，不用知识库未提供块事后辩护。
- 对事实/规则逐项摘录可见回答原文，标记支持、不支持、不确定或不适用，写出证据对应关系。可将同一事实的同义重述合并，但不能合并掩盖无依据的新增操作。
- 当前证据未授权的常识性处理步骤或企业裁决规则均为不支持；“按更严格政策处理”等看似保守的附加制度也不能免检。
- 引用支持性检查结论与编号对应证据，缺少必要引用另计。合法 `[1]` 不自动获得语义通过。
- 可答任务必须回答必要要点；部分可答任务需说明有据部分与未知边界。全部拒绝可答任务、空回答、纯模板话术不能获得完美质量分。
- 无答案任务正确说明缺乏依据可以通过。不把拒答中的“没有证据”当成需要额外编造的业务事实。
- 工具回答根据本次实际工具数据检查，模拟数据必须明确标注；不能由模拟正常状态推断真实系统正常。
- 成功任务须同时满足结构/数据库终态、全部必要要点、禁止行为和语义审阅。未知不自动通过，也不被偷换成确定失败。

示例：回答“P1 紧急，但当前资料没有解决分钟数”，只有取得优先级定义和时限边界两项证据时才能给对应要点通过。如果只取得边界块，则不得用整个语料中的定义证明该回答有据。纯回答“无法回答”在部分可答场景仍有遗漏。

## 分母与失败归因

报告意图轮次分子/分母、必需工具完成与实际调用合法性、参数有效性及多余调用数。必要证据齐全率以已审可答/部分可答任务为分母，并同时报告审阅覆盖；整体下界保留全部预定任务。

回答要点覆盖分别报告累计支持要点/累计要点，以及逐任务比例的均值。含无依据陈述比例的分母为具有可核查陈述的已审知识任务；空回答和纯拒答该项不适用，另受完整性/错误拒答/任务成功约束。引用关系逐条报告，缺失引用独立统计。

输入/身份、Router、实体/澄清、工具选择/执行、候选召回、证据筛选、生成、编号校验、审批/存储、执行控制、评测器错误分别归因，支持主因/次因/待定位。

基础设施错误、评测器错误、未执行和待审都保留在预定任务总分母中。重复尝试按首次尝试形成主任务结果，全部尝试留档与计费，不用成功重跑替代失败。不同运行分别汇总，配对按 case_id 比较，不把两组当作样本翻倍。

## 实验与费用

主质量实验检索缓存关闭，单 worker、串行低速，实际调用 DeepSeek v4 pro、温度 0、最大输出 1800 token、无模型自动重试，既有 Embedding 重试按实际物理调用入账。独立数据库/用户/会话/Redis namespace；服务和设备工具仍是模拟数据。SSE 使用代表性任务，不全面重复。

全阶段上限 30 元、物理调用上限 1200、保留至少 1 元余量；每个调用先预留估价，未知用量保留 null 并停止后续付费运行。成本账本以唯一调用 ID 汇总，不重复加总派生报告。估价使用保守高峰未缓存价，非供应商账单。

开发集用于选择候选；候选实现和评测器冻结后才运行留出对照，完成两组之前不据留出结果调整。P95 固定为排序后的 `floor((n-1)*0.95)`，不拼接 Phase 5 不同口径的历史百分位。收益允许为零或负，不能靠隐藏遗漏、拒答或失败得到提升。
